# ChatGPT plan integration (Sign in with ChatGPT)

Status as of 2026-10-12: implemented and verified locally. **Real Plus/Pro sign-in, account model listing, report generation, transcript judging/cleanup, read-only agent tool calls and local/remote sign-out passed using an isolated profile.** The current source suite passed 1100/1100 tests; packaged background scenarios passed 27/27, installed CLI outcomes 10/10, standalone smoke 1/1 and existing cutoff UI cases 2/2. All 30 successful test-app PIDs were absent from the follow-up's 962 OS-activation/frontmost observations. OpenAI API audio transcription is NOT-RUN because only a Plus/Pro account is available. Refresh was not forced before the provider's `earliest_refresh_at`; the isolated grant was revoked and its credentials removed after verification.

## 1. Goal

Replace the unofficial "Codex" provider with OpenAI's official Sign in with ChatGPT (SIWC) open-source plan-usage flow, and replace Codex transcription with the standard OpenAI API transcription endpoint billed to the user's own API key.

The old provider reused the Codex CLI's OAuth client through pi-ai and sent inference to `chatgpt.com/backend-api/codex/responses`. The SIWC documentation says "do not point it at ChatGPT's backend-api endpoints". Its transcription path sent that Codex bearer to `api.openai.com/v1/audio/transcriptions`.

## 5. OpenAI API transcription (`src/openaiTranscription.ts`)

`transcribeOpenAiAudio({ apiKey, audioFilePath, model, prompt?, language?, temperature?, signal? })` is the old `transcribeCodexAudio` with one change: it takes a standard OpenAI API key (`openaiApiKey`) instead of an OAuth token provider. It has no OAuth input at all, so a ChatGPT sign-in token cannot reach the transcription endpoint by construction. Results and error contracts are unchanged:

- returns `참가자N:`-labeled text for diarized output, and plain text otherwise
- `EmptyTranscriptionError` for silence (empty `text`, zero segments, or all-empty segments); a generic `Error` for malformed responses
- `TranscriptionApiError` with status, request id, error type/code, and a raw body capped at 1,500 characters
- the caller's `AbortSignal` is forwarded into `fetch`
- an empty API key throws before any network call

Request fields per model (from the speech-to-text guide):

| Model                                                      | `response_format` / `chunking_strategy` | `prompt` (`knownWords`)             | language field | `temperature`                           |
| ---------------------------------------------------------- | --------------------------------------- | ----------------------------------- | -------------- | --------------------------------------- |
| `gpt-4o-transcribe-diarize` (default)                      | `diarized_json` / `auto`                | omitted ("doesn't support prompts") | `language`     | omitted                                 |
| `gpt-transcribe`                                           | default JSON                            | sent                                | `languages[]`  | omitted (not documented for this model) |
| `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `whisper-1` | default JSON                            | sent                                | `language`     | sent when the caller sets it            |

The diarize model stays the default because it is the only documented model that labels speakers. `gpt-transcribe` is not in the curated picker; it can be entered through Custom... in Settings. Its guide documents no diarization, so choosing it drops speaker labels, and it has no `MODEL_PRICING` entry, so its usage is recorded as $0 with an unknown model. Before the 2027-02-26 shutdown, a diarizing successor (or a different STT default) has to be chosen. That decision is open.

Segmentation, format remux, and the 24 MB per-request cap remain properties of the `openai` batch backend (`src/batchSttBackend.ts`). They are unchanged from the Codex backend.

- **Summary provider**: `Gemini API` | `ChatGPT plan (Sign in with ChatGPT)`. Codex is no longer offered. A stored `codex` value is normalized to `chatgpt` in the integration layer, and the select falls back to its default if a value has no option.
- **Transcription service** (Transcription and summary tab): `Follow summary provider (Gemini only)` | `Gemini` | `OpenAI API (billed to your API key)` | `Soniox`. With ChatGPT selected, `auto` shows that recording transcription is off (text features on existing transcripts keep working). Saving a text-only ChatGPT setup is allowed; audio work refuses at run time until an explicit backend is chosen, and nothing falls back to another vendor. Choosing OpenAI without an API key, or Soniox without a Soniox key, shows a warning.
- **ChatGPT card** (shown when ChatGPT is the summary provider; ChatGPT never carries audio, so no transcription or live-caption choice shows it, `credentialUsage` in `src/settingsVisibility.ts`):

  - plan badge, independent of the connection line: plan usage enabled; "Signed in for identity only" (`planState: 'not_granted'`, consent declined); or "needs to be enabled again" (`planState: 'incomplete'`, plan scope without a renewable token pair);

When the active saved account is signed out it sends `loginChatGPT({ profileId })`, so main reauthorizes that registration with its issued client ID instead of registering a duplicate. After an identity-only or incomplete grant, the same button becomes **Enable ChatGPT plan**, which sends `loginChatGPT({ requestPlanConsent: true, profileId })` so main re-prompts with `prompt=consent`. Ordinary sign-ins never force consent. The button is hidden once plan usage works;
  - **Cancel sign-in** (shown while a sign-in is pending; aborts the loopback in main), **Sign out** (signs out the active account; warns when a revocable grant existed and OpenAI did not confirm revocation);
  - **Account or workspace** select plus **Add account**: each account signs in separately, and switching applies to new jobs only. `listChatGPTProfiles()` loads on every status change whether or not the active account is signed in, and the group stays visible while any registration is saved, so after signing out of account A the user can still select a connected account B or add another. Signed-out accounts are listed as "(signed out, sign in again to use)"; selecting one runs no model listing or inference until it is signed in with plan usage. Option labels use the optional `profile.label` from main when present; otherwise an email shared by another saved registration (or a missing email) gets the suffix "· registration <first 8 characters of the registration id>", which is stable across reloads, sign-outs and switches. No workspace name is invented;
  - an error notice region; errors with code `usage_limit_exceeded`, `usage_unavailable`, or `not_eligible` (main's SIWC codes without the `subscription_sharing_` prefix) get their own guidance and make **Manage usage** the primary action;
  - **Summary model** select populated from the signed-in account (`listChatGPTModels`), with **Refresh list**, and "Using ChatGPT plan · Manage usage" next to it when plan usage is active. A saved model the account does not list stays selected and is labeled "(not available for this account)", so it is never silently substituted. While signed out or in identity-only mode, the select is disabled and keeps the saved value.
- **One-time plan dialog** (`<dialog id="chatgptPlanDialog">`): "You're using your ChatGPT plan", explaining what runs on the plan and that transcription is billed by the chosen STT provider. **Got it** persists `chatgptPlanNoticeAcknowledged=true` immediately, independent of Settings Save. Escape closes it without acknowledging, so it appears again after the next successful sign-in.
- **Legacy transcription value**: a stored `transcriptionProvider=codex` (reported as `transcriptionProviderIssue.issue === 'legacy-codex'`) shows a disabled, selected placeholder option `Codex (removed): choose a provider` (`value="legacy-codex"`) with a notice explaining the removal. - **OpenAI API** group: `openaiApiKey` (shared by OpenAI transcription and OpenAI Realtime live captions) plus the transcription model picker (diarize default, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, Custom...). `gpt-transcribe` is Custom-only because it is unpriced.

Accessibility and safety:

- Only native `<button>`, `<select>`, and `<dialog>` elements are used, so keyboard and screen-reader behavior comes from the platform. Status and notice regions are polite live regions, and the card sets `aria-busy` while a sign-in is pending. Focus moves to Continue with ChatGPT after a cancel, and to the relevant button after sign-out. The plan dialog returns focus to its opener on close.
- No new text-entry handler triggers an action on Enter, so no new IME composition paths were added; the existing known-words handler keeps its `isComposing` guard.
- Closing Settings (button or Escape) bumps the sign-in and model-list tokens and calls `cancelChatGPTLogin()`, so a late result cannot update a closed modal and the loopback is released.
- The renderer never receives tokens. It sees only `{ connected, planEnabled, profileId?, email? }`, profile display rows, and model `{ slug, display_name }`.

## 7. Migration from the Codex provider

- Old `config.json` values (`aiProvider=codex`, `codexOAuth`, `codexModel`, `codexTranscriptionModel`, `transcriptionProvider=codex`) are kept on disk for explicit migration and are never used for a request.
- Old tokens (stored `codexOAuth`, `CODEX_OAUTH_*` / `OPENAI_CODEX_*` environment variables, and `~/.codex/auth.json`) are never read. They cannot be converted anyway: SIWC uses a different client registration, audience, scopes, and endpoints. Every user gives fresh consent through Continue with ChatGPT.
- `transcriptionProvider=codex` and `auto` under ChatGPT refuse with a message that names the explicit choices (`gemini`, `openai` + `openaiApiKey`, `soniox`). Nothing redirects audio or billing automatically.
- CLI: `listener chatgpt login|logout|status|models|accounts|use <id>`. `listener codex login|status|logout` print a deprecation warning and forward to `listener chatgpt` (a new SIWC sign-in, never the old Codex login); other `listener codex` subcommands are refused. Like the old command, `listener codex login` selects `aiProvider=chatgpt`, but only after a sign-in that granted plan usage; a failed, cancelled, or identity-only sign-in leaves the selection unchanged. `listener chatgpt login` never changes `aiProvider`.

## 8. Privacy

- New endpoints: `auth.openai.com` (sign-in, token, revocation, JWKS) and `api.openai.com/v1/models` and `/v1/responses` with the user's ChatGPT access token. Prompts sent there contain transcript text. Audio never goes through the ChatGPT sign-in.
- OpenAI transcription sends audio to `api.openai.com/v1/audio/transcriptions` with the user's own API key.
- Tokens live in `getDataPath()/chatgpt/credentials/` (0600, atomic writes), never in `config.json`, never in the renderer, never in logs or Sentry events.
- `docs/privacy.md` was updated accordingly (dated 2026-10-12).

## Background UI verification

`NODE_ENV=test LISTENER_BACKGROUND_TEST=1` explicitly opts an isolated test app into hidden windows from construction, with focus disabled, Dock/taskbar hidden, background rendering unthrottled, and no tray, global shortcuts, accessibility permission request, developer tools, automatic updater or device-detector startup. Normal application launches retain their existing behavior.

The main process passes a dedicated preload argument only for this mode. Before the renderer executes, the preload installs a non-visible JavaScript dialog observer (`window.__listenerBackgroundTestDialogs`); tests inspect its events and explicitly choose synthetic confirmation/prompt results. This tests application branches and does not prove the native OS dialog or assistive-technology experience. The harness must reject an older artifact lacking background support before launching it, and must never use a foreground fallback.

The separate GUI executor verifies visibility, focusability, focus, Dock state, shortcut registration and native show/focus/restore events using the packaged app. Read-only OS activation observations are recorded separately; hidden-window checks alone are not a measurement of the frontmost application. No ordinary user recordings or credentials are used.

Live text-path evidence: `/tmp/listener-chatgpt-live-text-opus/report.md` and `results-live.json`. Nine production Responses requests passed: one report, five judge/cleanup calls and three agent turns with two read-only tool round trips. The isolated grant's revocation returned HTTP 200, its local credential record was removed, and the old access token was rejected with HTTP 401. The harness initially used an over-strict HTTP response-header predicate; semantic checks and production completed-stream validation passed, while absent response headers remain an observation rather than a product failure.
